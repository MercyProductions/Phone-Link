# Bluetooth phone book

Open **Contacts → Bluetooth phone book (read-only)**, select your paired iPhone, and choose **Read phone book**. This uses the phone's PBAP service rather than the iPhone companion. It requires Windows RFCOMM access and any contact-sharing permission the phone presents. The older companion-sync list is independent and unchanged on disk.

For a less intrusive check, choose **Check count only** after selecting the phone. The app sends one size-only `PullPhoneBook` request for the main phone book (`MaxListCount=0`) and expects one bounded response with a `PhonebookSize` parameter and no contact body. An unexpected body, malformed reply, refusal or timeout does not become a count of zero, and the app does not fall back to reading a page. A valid count is what the selected phone reports for this repository; it does not establish access to individual contacts or call history. The count stays in the current view and clears on selection change, collapse, lock, or navigation.

The connection is encrypted and reads only the main `telecom/pb.vcf` phone book, 100 entries at a time, as UTF-8 vCard 3.0. Each result is bounded to 128 KiB; the request selects name and telephone fields only. Next and Previous explicitly request another page. The preview retains up to eight unique numbers per card; email, notes, photos, SIM contacts and call-history objects are not requested or displayed. Nothing is written to the phone or merged into the saved contacts. Closing the section, changing selection, navigating away, or locking Phone Link clears the preview.

The separate **Calls → Bluetooth call history (read-only)** view lists paired peers and, after explicit selection, requests up to 30 entries from one folder: **Combined** (`telecom/cch.vcf`), **Incoming** (`telecom/ich.vcf`), or **Outgoing** (`telecom/och.vcf`). It requests name, telephone and call-time fields. A failed or empty read does not automatically try any other folder. Phone Link does not request the missed-call-only object, send the missed-call reset parameter, or invoke call control. Reported timestamps are labeled as the phone’s local time, not converted to the PC’s timezone. Unrecognized directions and missing or malformed times are shown as unavailable. Call history clears on device or folder change, lock or navigation, and is never saved. Scripted tests verify the exact wire request for each folder; physical incoming/outgoing reads are not yet verified.

November 7 Calls smoke check: in the standalone `f36f979` build, a read for the identified paired iPhone completed successfully with zero permitted combined-log entries. This shows the read path answered, not that Recents was empty or that populated call history is available. The empty-result message now explains this distinction. No call or audio route was requested, and no call records were retained.

Verification: scripted exchanges validate the PBAP request target, repository, offset, and property mask; parser tests cover folded names, escaped names, grouped telephone fields, duplicate numbers, and malformed cards. Existing MAP wire tests still pass after sharing the bounded OBEX implementation. The count-only update built with zero warnings/errors and all 602 .NET tests passed.

November 7 Windows smoke check: in the standalone build from `f36f979`, the live Contacts view showed a successful count-only response and, separately, a successful permitted contact-page response for the user-selected Bluetooth peer. Verification retained only the status classification, not the peer identifier, count, names, or numbers. This is one successful pairing and session; it does not establish full phone-book coverage, call-history access, message access, or behavior in a registered Windows package. A PBAP service advertisement alone does not establish contact access.

Protocol reference: [Bluetooth SIG Phone Book Access Profile 1.2.3](https://www.bluetooth.com/specifications/specs/phone-book-access-profile-1-2-3/).
